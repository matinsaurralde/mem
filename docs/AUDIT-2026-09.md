### 0.1 Terminal noise captured as commands

Two lines in `~/.mem/repos/Users-matinsaurralde-Documents-repos-investigations-1f37839d.jsonl`
had commands `65;50;35M` and a 1,689-character `35;165;16M35;160;16M…`, both
exit 127, both from 2026-09-10 15:09. They are SGR mouse reports
(`CSI < button ; column ; row M`) with the `ESC [ <` prefix gone. The entry
right before them is `claude`, which ran 19.6 hours and exited **139**
(SIGSEGV). A program that dies with mouse tracking on never sends the disable
sequence, so the terminal (Ghostty, no tmux) kept reporting every mouse move
to the idle prompt; button codes 35 (motion) and 64–67 (wheel) are exactly
"scrolled and moved the mouse over a prompt". Eighteen minutes later the
payload reached the command line, Enter ran it, zsh split on every `;`
(exit 127 per piece, 703 ms for ~170 words), and `mem.zsh:36` (preexec stores
`$1` verbatim) plus `mem.zsh:48` (precmd calls `mem _capture`) stored it.
`fix.py` then selected it as the last failure because it selects any non-zero
exit code.

**The finder is not the source.** `tui.py` writes only alt-screen and cursor
sequences; no `?1000h`/`?1002h`/`?1003h`/`?1006h` anywhere; restore is a bare
`finally`. The owner's `.zshrc` also sources `fzf --zsh` after `mem init zsh`,
so Ctrl+R in that shell is fzf's and `mem tui` was likely never invoked there.

Caveat on the record: feeding raw `ESC [ < 35;165;16 M` to an interactive
zsh 5.9 on a pty in eight variants (single write, byte by byte, gaps, vi
keymap, the owner's own rc with autosuggestions/syntax-highlighting/starship/
fzf) always made zle discard the whole report. Something upstream of zle
delivered the payload without its prefix; that step was not reproduced. The
capture-side filter is the right defence regardless.

**Fix.** `capture.looks_like_terminal_noise` matches a line that is nothing but
mouse reports (`(?:(?:\x1b\[<|\[<)?\d+;\d+;\d+[Mm])+`, full match on the
stripped line) and `capture_command` returns before the git subprocess, the
session tracker and the sync counter, silently, like every other skip on the
capture path. `echo 65;50;35M`, `awk '{print $1;$2}'`, `sleep 1;ls` are kept.
Bracketed-paste markers and X10 reports are deliberately left out (the shells
handle the former; the latter is not printable). Tests use both real strings
verbatim (`TestTerminalNoise`, 21 cases) and were watched go red with the
predicate inverted. No hook change was needed.

**Existing entries: not migrated by code.** `mem forget` already does this
safely: substring match, preview and a `Delete all 2?` prompt defaulting to
No, rewrite under `exclusive_lock` via `atomic_write`, the one session whose
only command is noise removed whole, `picks.json` untouched (and absent on
this machine), patterns/groups/vars/audit verified no-ops. A custom migration
would duplicate `forget_commands`. The only thing `forget` lacks is a backup,
which is one `cp`. The backup was taken (`~/.mem.bak-2026-09-21`, verified
identical with `diff -rq`); the sandbox refused to run the deletion, so it is
left to the owner:

```bash
mem forget '65;50;35M'          # answer y at "Delete all 2?"
grep -rc '65;50;35M' ~/.mem     # every count 0
mem fix                         # no longer reports the noise
# rollback: rm -rf ~/.mem && mv ~/.mem.bak-2026-09-21 ~/.mem
```

Loose end, recorded: `mem import --from-shell-history` bypasses
`capture_command`, so the same garbage in a history file would be imported.
The owner's `~/.zsh_history` does not contain it today.

### 0.2 No results printed nothing

Two separate defects.

- **`mem zzz --json` printed nothing: option parsing, not the empty branch.**
  The JSON branch already emitted `[]` for `mem --json zzz`. But Click stops
  reading the group's options at the first positional, and the implicit-search
  router joined everything after it into the query, so a trailing `--json`
  became the text "zzz --json" and took the human path. Same for a trailing
  `-n 3`, `-p`, `--help`. The README documents `mem deploy --json` and
  `mem deploy -n 20` (lines 126–127); neither worked. The router now re-parses
  the line once it knows the first positional is not a subcommand, with mem's
  own options allowed anywhere and unknown dash-words kept as query text
  (`mem git commit -m` still searches for what it says; `--` forces literal
  text). Visible consequence: `mem grep -n` with no value is now a Click usage
  error (exit 2) rather than a silent search for "grep -n"; quote it or use
  `--`.
- **Human path silence was never a decision.** The `return  # Empty results,
  no error (exit 0)` dates from the first commit (`f0164c5`) with no rationale
  beyond the exit code; `specs/001-v1-core/spec.md:30-32` talks about the exit
  status, not muteness; the pinning test from `7d235db` only asserted
  `stdout == ""`; no ADR, CHANGELOG or PHILOSOPHY line covers it; every other
  command prints something when it has nothing. Silence is indistinguishable
  from a broken hook, an empty store, or a swallowed flag, all three of which
  have happened. Now: one dim line on stderr, `no matches for "…"`, stdout
  empty, exit 0. `mem --help` says so.

Not fixed, for the record: `session`, `fix`, `promote`, `list`, `forget` and
`-p` print their no-data message on **stdout**, contradicting Philosophy III
and now the search path; and the three JSON "nothing" shapes differ (`[]`, a
stats envelope, a fix envelope with `failure: null`).

question 14. All three benchmarks state their basis in docstrings; none cites
an ADR.

## Phase 2 results

38 commits on `audit/2026-09` after the release commit: 4 from Phase 0, 34
from the list above. Each was cherry-picked onto the branch one at a time and
followed by `ruff check`, `ruff format --check` and the full suite including
`test_e2e.py` and `test_hooks_e2e.py`; none went red. Final state:
**1,520 passed, 4 skipped, 18 deselected, 0 warnings, ~60 s, 92 % branch
coverage** (from 1,450, 268 warnings, 69 s and 91 %), and the suite passes
under `-W error`. Run again by hand on the final tree: `ai` 2 passed, `perf`
4 passed, `keychain_live` 12 passed.

Deviations, stated because the list said what it said:

- Item 8 (magic-number comments) touched eight files in one commit, and items
  5 and 7 touched four; all three are comment-only with values unchanged. The
  brief's three-file limit was read as applying to code.
- Item 9: `MAX_CONCEPT_WORDS` was kept, because it is also the parse-time cap
  in `concepts._parse` and deleting it would have admitted four-word keys; the
  redundant `min()` and the duplicate filename constant went.
- Item 14: in `tui.py` the two functions became aliases of `ranking.terms`
  and `ranking.matches` rather than being deleted, so their call sites did
  not move.
- Item 17: the three Pydantic readers (`read_commands`, `read_sessions`,
  `read_agent_audit`) were not routed through the new `iter_jsonl_objects`,
  because they parse with the model's own JSON parser and already skip a
  non-object line; decoding twice would double the cost of the one path the
  module measures in milliseconds. The four rewriters, the migration and
  `groups.get_last_captured_command` are on the helper; eight pinning tests
  went red before the fix. Also found: `rotate` writes each file as it goes,
  so a bad line stopped retention only for that file and every file sorted
  after it, which is why the stall was never global.
- Item 18: only the write in `_save_state` is under the lock, not the whole
  of `update()`, because a session boundary calls the on-device summary
  model and holding the global lock for those seconds would stall every
  other shell's capture. The read-modify-write race between two shells is
  unchanged.
- Item 13: `think_seconds` clamps at zero (promote's behaviour); `fix`'s only
  caller already skipped negative gaps, so no `mem fix` result changes.
- Item 16: with the SDK installed but the model off, `sync_all_patterns` now
  falls through to the heuristic and prints the "install AI support" tip,
  which is wrong for that user; one-line follow-up.
- Item 7: `detect_credentials` and the two SDK calls in `patterns.py` keep
  `except Exception`, with the comment naming the SDK's exception tree
  (`FoundationModelsError > GenerationError > …`) and the bare `ValueError`s
  the SDK raises outside it. `_load_state` now validates with
  `model_validate` so a JSON list is a `ValueError`, not an uncaught
  `TypeError`.
- Item 19: the session-boundary change is a behaviour change to `mem
  session`; it is the fourth instance of the bug CLAUDE.md names and ADR-012
  already records the tracker as wrong, so it was made with a test rather
  than deferred. The 300 s boundary test with no duration is untouched.
- Item 20: the `tui` fix keeps first-frame cost flat (heap merge over file
  starts: 0.42 ms vs 0.39 ms for the wrong walk on 20k lines; extracting
  `ts` from every line would have cost 5.7 ms, a quarter of the ADR-008
  budget).
